01 / Inspection layers

What the gateway checks,
in order.

Each layer is a separate detector with its own failure mode. A request must pass the sequence before it reaches a tool or a model.

  1. 01

    Injection detection

    Pattern-based detection of instruction override, role reassignment and exfiltration attempts across prompt and payload.

    Regex + heuristics
  2. 02

    Trust boundary

    Marks every input segment as trusted or untrusted, so downstream code never has to guess whether a string came from a user.

    Segment labelling
  3. 03

    Vault lookup

    Resolves which scoped credentials a request may touch. Unscoped or expired credentials are not returned.

    Scoped resolution
  4. 04

    Policy engine

    Evaluates declarative rules from configuration. Tool calls outside the allowlist are blocked or escalated, never silently permitted.

    YAML + defaults
  5. 05

    Session risk

    Tracks cumulative risk across a session rather than per request, so a slow escalation across many calls still trips the threshold.

    Cross-request state
  6. 06

    Governance headers

    Returns the decision, the reason and the trace identifiers as response headers the calling system can assert on.

    Machine-readable

03 / Engineering status

What is verified,
and what is not.

Stated plainly so a security review starts from the real position rather than the marketing one.

Verified in the development pipeline

  • Dashboard build completes
  • Docker startup reaches a healthy state
  • Gateway health endpoint responds
  • Security regression tests pass
  • Bounded benchmark dataset runs end to end
  • Live SDK contract tests cover authentication, rejected requests and gateway availability

Passing these checks is evidence of internal correctness. It is not a production security certification and no third party has audited it.

Still required for production

  • Configured credentials and secret rotation procedure
  • Independent integration validation against target systems
  • Dependency review and vulnerability scanning
  • Operational hardening: rate limiting, failover, alerting
  • Threat model sign-off for the deployment context

Until these are addressed, treat OmniGuard as a development preview.

04 / Integration adapters

One gateway in front
of the portfolio.

The gateway ships with adapters for each system in this portfolio, so inspection is added once rather than per project.

AgentGuardPolicy

Delegates tool-call policy evaluation to the existing policy engine.

Agent EvalVerdict

Forwards inspection outcomes into evaluation traces and metrics.

Hybrid-RAGContext

Validates retrieved context before it enters a prompt.

AgentVaultCredentials

Resolves scoped credentials through the vault rather than the gateway.

FoundationCentarGovernance

Supplies approval state for governed orchestration steps.

Pharma OSHuman review

Routes cases requiring qualified human verification.
