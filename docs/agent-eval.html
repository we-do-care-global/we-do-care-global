01 / Project focus

Measure the workflow,
not the model.

A model answer can be correct by luck. Agent Eval measures what actually happened: which tools were called, whether they succeeded, and whether policy held.

Task successDid it finish?

Whether the workflow reached its declared end state, counted against a stated definition of done.

Tool accuracyDid it pick right?

Whether the tool sequence matched the reference path, and how many calls were wasted.

Policy complianceDid it stay in bounds?

Whether every call passed policy evaluation without an override or bypass.

LatencyHow long?

Decision and end-to-end latency at a declared percentile, not an average.

03 / Scope and verification

Where the line is.

Evaluation tooling is a means, not a verdict. What counts as good performance has to be defined by you.

Not a correctness claim

Published evaluation tooling does not certify model correctness. Test coverage, datasets and acceptance thresholds need to fit your use case.

Source and publication

Source availability and publication records do not certify the current Next revision. Review release notes, tests and deployment assumptions for your environment.
